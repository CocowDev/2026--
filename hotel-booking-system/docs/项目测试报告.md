### 🟠 P1 设计缺陷（影响数据正确性 / 可维护性）

| # | 位置 | 问题描述 | 建议 |
|---|------|----------|------|
| 6 | [Booking.java:49](backend/src/main/java/com/hotel/booking/entity/Booking.java) | `totalPrice` 用 `Double`，DB 为 `DECIMAL(10,2)` | 改用 `BigDecimal` 避免精度丢失 |
| 7 | [Booking.java:33-37](backend/src/main/java/com/hotel/booking/entity/Booking.java) | `checkInDate`/`checkOutDate` 用 `String`，DB 为 `DATE` | 改用 `LocalDate` |
| 8 | [BookingMapper.java](backend/src/main/java/com/hotel/booking/mapper/BookingMapper.java) | JOIN 查询 `user_name`/`user_phone`/`room_title` 列，但 `Booking` 实体无对应 `@TableField(exist=false)` 字段 | 关联数据被丢弃；应加 DTO/VO 字段或 `@TableField(exist=false)` |
| 9 | [BookingController.java:60-63](backend/src/main/java/com/hotel/booking/controller/BookingController.java) | `create` 手动从 header 解析 token 取 userId，而 [JwtAuthenticationFilter](backend/src/main/java/com/hotel/booking/security/JwtAuthenticationFilter.java) 已写入 SecurityContext | 改用 `@AuthenticationPrincipal Long userId`，避免重复解析与不一致 |
| 10 | [BookingService.java:92-94](backend/src/main/java/com/hotel/booking/service/BookingService.java) | `getRecentBookings()` 调 `findAllWithDetails()` 无 `LIMIT` | 仪表盘可能加载全表，加 `LIMIT` 或分页 |
| 11 | [DataInitConfig.java:28](backend/src/main/java/com/hotel/booking/config/DataInitConfig.java) vs [seed.sql:4](database/seed.sql) | 两套种子数据 admin 密码不一致：代码初始化为 `admin123`，SQL 哈希对应明文为 `admin` | 统一为单一数据源，避免混淆 |
| 12 | [SecurityConfig.java:33](backend/src/main/java/com/hotel/booking/config/SecurityConfig.java) | `/api/admin/**` 需 ADMIN 角色，但项目无 `AdminController`，管理员接口散落在各 controller | 路径与实际 controller 映射不匹配，`/api/admin/**` 规则实际未生效 |
| 13 | [BookingController.java:83-86](backend/src/main/java/com/hotel/booking/controller/BookingController.java) | `/export` 接口返回"导出功能开发中"占位 | 前端 `bookingAPI.export` 实际无数据 |
